Fases 1 y 2: Comprensión del Negocio y Datos

Definición y Hallazgos Iniciales

El proyecto aborda la problemática como una clasificación binaria para categorizar a los estudiantes en "En Riesgo" o "Sin Riesgo".

  • Análisis de Costos de Error: El error más crítico es el Falso Negativo (no detectar a un estudiante que va a desertar). Por ello, el Recall (Sensibilidad) es nuestro KPI principal.
  • Dimensiones Analizadas: Académicas (ICFES), Socioeconómicas (Valor pagado), Psicosociales (Ansiedad/Depresión) y Comportamentales.
  • Hallazgos: Se detectó un desbalance del 25% en la clase minoritaria y variables con escalas incompatibles que requerían tratamiento urgente.

Fase 3: Preparación de Datos (Data Preparation)

Tratamiento Estadístico Riguroso

Para asegurar que la Red Neuronal converja correctamente y no se sesgue, se aplicó un pipeline de transformación:

  • Feature Engineering: Agrupación de variables de salud mental (Ansiedad/Depresión) para crear perfiles de riesgo consolidados.
  • Normalización (Z-score): Uso de StandardScaler para que todas las variables numéricas operen en una escala común (media 0, desviación 1), evitando saturación de gradientes.
  • Balanceo con SMOTE: La clase de deserción era minoritaria. Se generaron registros sintéticos para equilibrar la muestra de 284/866 a 866 vs 866 registros (50/50).

Resultado de Fase 3: Datos 100% íntegros, normalizados y balanceados (Total: 1,732 registros listos para el entrenamiento).

Fase 4: Modelado (Perceptrón Multicapa)

Arquitectura y Entrenamiento

Se implementó un modelo MLPClassifier debido a que el riesgo de abandono involucra variables que no son linealmente separables.

  • Arquitectura: 64-32-1 (Dos capas ocultas de 64 y 32 neuronas).
  • Activación: ReLU para capas internas y Sigmoide para la capa de salida (probabilidad).
  • Optimización: Algoritmo Adam, límite de 500 iteraciones.

El entrenamiento se realizó con el 80% del dataset balanceado. El modelo alcanzó la convergencia de manera orgánica y estable.

Fase 5: Evaluación de Resultados

Validación del Sistema de Alertas

La métrica de Exactitud (Accuracy) es engañosa en contextos desbalanceados, por lo que el modelo fue evaluado en base a su capacidad real de detectar riesgo.

  • Recall Crítico: 0.98. Identifica al 98% de los estudiantes en riesgo real.
  • Precisión: 0.80. Las alertas generadas son altamente confiables.
  • F1-Score: 0.88. Equilibrio excepcional del algoritmo.

Como se observa en las gráficas adjuntas, el modelo cumple con el objetivo institucional fundamental: evitar a toda costa la omisión de estudiantes vulnerables.

Fase 6: Despliegue y Monitoreo Institucional

Protocolo de Acción (Intervención)

El modelo se ha integrado a una interfaz en Streamlit. Cuando la red neuronal emite una probabilidad P > 0.7 (Riesgo Muy Alto), se desencadena el siguiente protocolo:

  • Automatización: Correo de alerta inmediata a Bienestar Universitario y al tutor académico.
  • Entrevista Prioritaria: Cita obligatoria con trabajo social en menos de 48 horas.
  • Derivación Específica: Asignación a tutorías (si el factor es académico) o referenciación al comité de becas (si el factor es económico).

Mantenimiento Técnico

Para mitigar la degradación del modelo por Data Drift (cambios en el perfil de ingreso), se establece un re-entrenamiento semestral obligatorio y monitoreo constante a través del Dashboard central.
